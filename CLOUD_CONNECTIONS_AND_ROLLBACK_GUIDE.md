## 📌 Executive Summary

This document serves as the **complete, standalone rollback guide and cloud connection directory** for the **Little Flower Preparatory School (LFPS) Substitutions Manager & Master Routine Suite**.

If a catastrophic deployment, data corruption, or breaking code change occurs, this document provides the exact technical procedures to roll back both the **frontend client (GitHub Pages)** and the **backend Go microservice (Render)** to this pristine, verified milestone (Job Bundle 33 / Commit `bdd6fd3`).

## 3. Environment Variables & Manifests

### 3.1 Client Environment (`apps/web/.env`)
The client web application consumes these variables at build time via Vite:

```ini
# Production Cloud Endpoints
VITE_API_URL=https://lfps-substitutions-manager.onrender.com
VITE_WS_URL=wss://lfps-substitutions-manager.onrender.com
```

*For local offline testing, change these in `apps/web/.env` to:*
```ini
VITE_API_URL=http://localhost:8080
VITE_WS_URL=ws://localhost:8080
```

### 3.2 Render Server Environment Settings
Configured in the **Render Dashboard $\to$ Environment Variables**:

| Variable | Recommended Value | Purpose |
| :--- | :--- | :--- |
| `PORT` | `8080` | Internal HTTP listening port for Go standard library `http.ListenAndServe`. |
| `DATA_DIR` | `/app/data` | Path to persistent disk storage for JSON state snapshots and Excel exports. |

## 5. Step-by-Step Pristine Rollback Runbook

### Scenario A: Full Local Codebase Restoration (From Tarball)

If local source files are corrupted or you are setting up on a clean computer:

```bash
# 1. Create a fresh directory
mkdir -p LFPS_Restored
cd LFPS_Restored

# 2. Extract the pristine tarball
tar -xzf /path/to/LFPS_PRISTINE_ROLLBACK_v2.0.0_bundle33_*.tar.gz

# 3. Install NPM dependencies
npm install

# 4. Verify test suite (Expected: 19/19 passing)
npm test

# 5. Build production bundle
npm run build

# 6. Start local development server
npm run dev:web
```

---

### Scenario B: Frontend Rollback on GitHub Pages

If a bad frontend release broke GitHub Pages:

#### Method 1: Git Revert to This Pristine Commit (`bdd6fd3`)
```bash
# 1. Ensure you are on the correct branch
git checkout next-gen
git fetch origin

# 2. Hard reset to this pristine commit
git reset --hard bdd6fd3

# 3. Clean and rebuild production distribution
npm run build

# 4. Prune any stale hashed asset files
# (Ensure only the active index-*.js and index-*.css exist in assets/)

# 5. Force-push the pristine state to GitHub
git push origin next-gen --force
```
*GitHub Pages will automatically update within 30 to 60 seconds.*

---

### Scenario C: Backend Microservice Rollback on Render.com

If the Go server on Render encounters issues or fails to start:

#### Method 1: Instant 1-Click Rollback via Render Dashboard
1. Log into your [Render Dashboard](https://dashboard.render.com).
2. Click on the **`lfps-substitutions-manager`** Web Service.
3. In the left navigation, select **Events** or **Deploys**.
4. Locate the last successful deploy (matching commit `bdd6fd3` or earlier).
5. Click the three dots `...` next to that deploy $\to$ select **Rollback to this deploy**.
6. Render will instantly spin up the previous Docker image without rebuilding.

#### Method 2: Manual Trigger via Git
```bash
# Check out next-gen and verify backend files
git checkout next-gen
cd apps/server

# Verify Dockerfile builds locally (requires Docker daemon)
docker build -t lfps-server:test .

# If verified, push to origin/next-gen to trigger Render auto-deploy
git push origin next-gen
```

## 6. Verification & Post-Rollback Smoke Test

After performing a rollback on either frontend or backend, run this quick 4-step checklist:

### Step 1: Backend Health Check
Run in terminal:
```bash
curl -I https://lfps-substitutions-manager.onrender.com/api/v1/health
```
*Expected Output:* `HTTP/2 200` with JSON body `{"status":"healthy","uptime":"..."}`.

### Step 2: System Metadata Check
```bash
curl https://lfps-substitutions-manager.onrender.com/api/v1/meta
```
*Expected Output:* JSON displaying active clients, build version `2.0.0-alpha.1`, and Go runtime info.

### Step 3: Frontend PWA Load Test
1. Open `https://steph1420.github.io/LFPS_Substitutions_Manager/` in an incognito window.
2. Confirm that the **Dynamic Island Day Bar** displays smoothly.
3. Open the **Settings Modal** (gear icon) $\to$ check the **Live Cloud Sync** section:
   * Status indicator should display: `🟢 Connected` with active clients count $\ge 1$.

### Step 4: Substitution Solver & History Verification
1. Mark any Class Teacher (e.g. Mrs. M. Midha) as absent.
2. Verify that the **Off. CT squircle** appears.
3. Navigate to **Substitutions** tab $\to$ tap **Auto-Resolve**.
4. Confirm that candidates are allocated with zero double-bookings.
5. Press `⌘Z` (Undo) $\to$ verify that the resolution cleanly reverts.
